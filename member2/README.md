# Member 2 — Data preparation and initial analysis

Prepare GDP hourly drifter trajectories within **25–45°N, 80–50°W** and assess data availability for 1-hour, 1-day and 1-week forecasts. This rectangular window includes neighbouring waters and is not an exact Gulf Stream boundary.

## Pipeline

GDP hourly data → regional filtering → quality checks → continuous segmentation → EDA and forecast-window counts → Parquet export.

## Run

Use a Python environment with the packages in `requirements.txt`. The pinned scientific-package versions record the completed analysis environment.

```bash
cd member2
python -m pip install -r requirements.txt
python -m jupyterlab gulf_stream_eda.ipynb
```

Run cells from top to bottom. The first scan needs internet access and may take time. Extraction uses `MAX_WORKERS` parallel threads (currently 8); reduce this if memory is limited. Cached blocks allow resuming. `MAX_OBSERVATIONS=None` scans the full source; a smaller value is for debugging only. The regional subset is loaded into memory.

The repository notebook has saved outputs cleared to avoid stale progress and local paths. The completed figures and statistics are included below. The local working notebook is unchanged.

## Results

Full-scan outputs: [`member2_outputs/full_25edd24008c2/`](member2_outputs/full_25edd24008c2/).

- 8,138,225 regional records from 1,481 drifters, November 1990–October 2022.
- 5,725 continuous segments; median duration 288 hours (12 days).
- With a 24-hour history, 1,465 / 1,455 / 1,394 drifters provide windows for 1 / 24 / 168-hour forecasts.
- The one-week task has 7,403,575 overlapping candidate origins, not independent samples or evidence of prediction accuracy.
- SST is 3.39% missing. No missing timestamps, duplicate drifter–time pairs or missing velocity components were found in the regional subset.

## Modelling handoff

Keep forecast windows within a single `segment_id`. A continuous segment requires the same drifter, adjacent source indices and exactly one-hour intervals. A 24-hour history plus a 168-hour forecast needs 193 position points.

Split training, validation and testing by `buoy_id`; the sample is a development subset, not a test split. Fit imputation, scaling and mean flow on training data only. Times are UTC (stored as timezone-naive timestamps). Current windows require all historical and future positions to stay inside the region. Forecasts beyond the boundary need additional extraction. Check source quality flags and whether velocity estimates use future information before modelling.
